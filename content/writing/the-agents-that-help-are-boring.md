The last useful agent I saw was not answering questions in a chat window. It was filling out the same activation form a specialist had been copying by hand, five or six times a shift.

Nobody would put that in a launch video. The specialist would notice if it disappeared tomorrow.

## The flashy version is a bad compass

A lot of agent ideas start with the model. What if it could research the account, draft the note, and book the follow-up. That demo is easy to picture and hard to trust, because nobody can point to the hour it gives back.

The better starting point is a job that already exists. Someone does it on a schedule. They complain about it. When they are out, it piles up. That is the job.

I learned this watching work move through call centers and product operations. The expensive part was rarely the decision. It was the retyping. An account number from one system, an address from another, a note that had to land in a third place before the next person could move.

## Sit with the person who does it

Don't start with a workshop about AI. Ask someone to do the task while you watch. One real example is enough.

Watch where they hesitate. Watch what they copy. Ask what happens when a field is wrong, because that is the part an agent will get wrong too.

You want a task with a clear start and a clear finish. A new order comes in. A document arrives. A list has to be checked every morning. If you cannot say what "done" looks like, you are not ready to hand it to an agent.

## Write the job down before you pick a tool

I keep this short on purpose:

- What kicks the work off?
- What does the person look up, and where does it live?
- What do they hand to the next person?
- What do they still need to check themselves?

That last question is the one people skip. An agent that files something nobody reviews will eventually file the wrong thing. An agent that prepares the work and leaves the odd cases for a person is usually the one that sticks.

## Build one pass, then time the cleanup

Take a real example from last week, not a tidy sample you invented. Run the smallest version that gets through one pass. Then compare it with how the job gets done today, and count the time someone spends fixing the output.

If the checking takes as long as doing it by hand, you do not have a win yet. You have a draft. Narrow the job until the person would rather start from that draft than from a blank screen.

When that happens, the next version is obvious. You also have something concrete to show. Here is yesterday's work. Here is what the agent produced. Here is what the person still had to touch.

Start there. The clever agent can wait until the boring one is earning its keep.
